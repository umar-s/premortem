# premortem

Скилл для Claude Code: структурированный premortem по конкретному плану,
запуску, найму или решению — за 10–15 минут находит дыры, которые иначе
всплывут уже после провала.

[English](README.md)

---

## Зачем нужен

Запускаете продукт — кажется всё продумано. Через три месяца лежит. И всё это
время Claude бодро поддакивал: «Да, отличный план, успехов!»

Это не баг конкретной модели. Это базовое поведение всех LLM. Спросите
«что может пойти не так?» — получите общие, смягчённые, политкорректные
ответы. Спросите «это хороший план?» — модель найдёт причины сказать «да».

**Premortem ломает паттерн.** Не «оцени план», а «представь что план уже
провалился — расскажи как именно он умер». Мозг переключается в режим
нарратива и вместо хеджирования выдаёт конкретные, креативные, честные
причины.

Mitchell, Russo и Pennington (1989) измерили: формулировка в прошедшем
времени даёт **~30% больше конкретных причин** будущих провалов, чем
условная. Канеман назвал premortem своим единственным самым ценным
инструментом принятия решений.

Скилл переносит метод в Claude Code как воспроизводимую сессию с
детерминированной механикой и сохранением истории.

---

## Что делает

Сессия состоит из четырёх фаз:

- **Pre-flight** — синхронизирует контекст с тем, что уже есть в проекте
  (CLAUDE.md, прикреплённые брифы), не задаёт лишнего.
- **Silent scan** — три параллельных помощника ищут дыры с шести углов
  (Клиент, Исполнитель, Противник, Допущения, ситуативный угол, и
  обязательно «Будущий поддерживающий» для WYSIATI-микрошага). Семантический
  дедуп оставляет 5–8 уникальных дыр.
- **Live диалог** — по каждой дыре скилл предлагает 2–3 стратегических
  варианта решения, юзер выбирает. Топ 1–3 раскрываются до полного режима
  (prevent / detect / стоп-условие / limit damage).
- **Запись** — атомарная запись в `docs/premortem/<plan-name>.md` плюс
  снапшот в `history/`. Через месяц можно перезапустить премортем на том
  же плане и сравнить: какие дыры закрылись, какие усугубились, какие
  появились новые.

В синтез встроены: outside view (Kahneman & Lovallo 2003), bias-проверка
по 6 пунктам из чеклиста Kahneman/Lovallo/Sibony (HBR 2011), и условный
reverse-премортем (Klein 2025) когда рекомендация = `delay`/`abort` —
защита от излишней осторожности.

## Как работает

### Фаза 1. Pre-flight (1–2 мин)

Скилл сначала сканирует доступный контекст — то, что уже сказано в чате
или лежит в файлах проекта. Спрашивает только то, чего не хватает. Минимум
для запуска:

- предмет (что запускаем / решаем)
- аудитория
- критерий успеха
- горизонт оценки (через 30 дней / 3 месяца / 12 месяцев / после первого
  пилота / после запуска)

Reference class спрашивается отдельно: «На что это похоже из уже сделанных
проектов?» — основа для outside view.

### Фаза 2. Silent scan (3–5 мин)

Скилл классифицирует тип плана и подбирает 6 углов под него. Запускаются
**три параллельных LLM-помощника одним сообщением** (по 2 угла на
помощника). Каждый возвращает максимум 2 дыры с маркером уверенности:
«подкреплено контекстом» / «требует проверки» / «предположение».

Hash-дедуп убирает явные дубли, семантический дедуп объединяет близкие
дыры с сохранением источников. Итог — 5–8 уникальных дыр, отсортированных
по важности × уверенности.

Юзер видит только список выбранных углов одной строкой и потом — список
готовых дыр.

### Фаза 3. Live диалог (5–8 мин)

По каждой дыре:

1. Описание дыры в одном абзаце + почему важно + угол + уверенность.
2. **2–3 стратегических варианта** решения с +/–. Не задачи — направления.
3. Юзер выбирает / просит другие варианты / откладывает / отвергает.
4. По выбранному фиксируется: что выбрали, почему, первый шаг,
   исполнитель (агент / человек / оба).

После прохождения всех дыр:

- Скилл сам отбирает топ 1–3 по важность × обратимость × уверенность.
- Топ раскрывается до полного режима: prevent / detect / стоп-условие /
  limit damage.
- **Bias-проверка топа.** Скилл предлагает наиболее вероятный когнитивный
  биас, который мог исказить решения, и конкретную коррекцию.
- **Session recommendation:** `continue` / `reduce_stake` / `delay` /
  `abort` — на основе паттерна принятых решений.
- **Reverse-премортем** запускается только при `reduce_stake` / `delay` /
  `abort`: «прошёл [горизонт]. Не сделали. Оказалось зря — почему?»
  Защита от premortem-смещения в сторону осторожности.

### Фаза 4. Запись (1 мин)

Один main-файл `docs/premortem/<slug>.md` плюс timestamped-снапшот в
`docs/premortem/history/`. Запись атомарная (tempfile + os.replace + fsync),
под advisory file lock. Любая последовательность запусков оставляет файл
валидным.

## Что получите на выходе

Один markdown-файл с YAML-frontmatter:

- **Контекст:** предмет / аудитория / успех / горизонт / reference class
- **Дыры** (5–8): id, title, угол, важность, уверенность, статус, описание,
  принятое решение
- **Топ 1–3** дыр в полном режиме: prevent / detect / стоп / limit damage,
  владелец, первый шаг
- **Bias-проверка** одной строкой
- **Session recommendation** + причина
- **Reverse-премортем** (когда применимо): 3 причины «почему могли зря не
  сделать» + что перевешивает
- **История запусков** с динамикой статусов: `same` / `worse` / `resolved`
  / `new`

## Когда применять

Скилл работает на конкретных, обратимых обязательствах с высокой ценой
ошибки. Хорошие случаи:

- **Запуск продукта / фичи.** «Выкатываем новый дашборд через 6 недель.»
- **Изменение цены.** «Поднимаем подписку с $19 до $39.»
- **Найм.** «Берём первого маркетолога, junior, $60k base.»
- **Контент-запуск.** «$297 live workshop по [теме] для [аудитории].»
- **Архитектурное решение.** «Переезжаем с monolith на микросервисы за
  квартал.»
- **Партнёрство / контракт.** «Подписываем 12-месячный exclusive с
  одним каналом дистрибуции.»

Минимальные требования: есть план в форме (не идея в голове), есть 10–15
минут, обязательство ещё не финализировано.

---

## Когда НЕ применять

- **Идея без формы.** Нечего ломать — сначала помоги план оформить, потом
  премортем.
- **Вопрос с одним правильным ответом.** «Какая модель быстрее?» — это не
  premortem, это факт-чек.
- **Творческая правка черновика.** Это редактирование, не premortem.
- **Уже принятое необратимое решение.** Premortem не вернёт назад.
- **Multi-perspective input на решение в настоящем времени.** Там лучше
  подходит LLM Council pattern, а не past-tense framing.

## Рекомендации по применению

- **Запускайте на этапе «план почти готов».** Слишком рано — нечего
  ломать. Слишком поздно — уже не повлияете.
- **Не пропускайте reference class.** «На что это похоже из уже сделанных
  проектов?» — самый дешёвый источник outside view. Если не знаете —
  скажите «не знаю», скилл двинется дальше с пустым reference class.
- **Не выбирайте «отложить» по дефолту.** Premortem систематически смещает
  в сторону осторожности — Klein 2025. Поэтому встроен reverse-премортем:
  спросит «а если зря не сделали?»
- **Перезапускайте через месяц.** История сравнит — какие дыры закрылись,
  какие усугубились, какие появились новые. Это ловит дрейф плана.
- **Не пытайтесь делать премортем на чужой план без контекста.** Сначала
  получите хотя бы предмет / аудитория / успех. Без этого выйдет общий
  риск-чеклист, а не премортем.
- **Принимайте 2–3 решения, не 8.** Если скилл дал 8 дыр и юзер принял по
  всем — это, скорее всего, иллюзия контроля. Премортем сработал когда
  топ выбран и есть конкретный первый шаг.

## Установка

**Требования:**
- Claude Code
- Git
- [uv](https://docs.astral.sh/uv/) — для запуска CLI-скриптов
  (детерминированная механика)

**Установка:**

```bash
git clone https://github.com/AndyShaman/premortem.git
cd premortem
./install.sh
```

Установщик копирует `premortem/` (SKILL.md, scripts, references, assets,
evals) в `~/.claude/skills/premortem/`. Тесты остаются в репо.

**Проверка:**

```bash
ls ~/.claude/skills/premortem/SKILL.md
```

Перезапустите Claude Code (или начните новую сессию) — скилл подключится
автоматически по триггерным фразам.

**Обновление:**

```bash
cd premortem
git pull
./install.sh
```

## Триггеры

Скилл подключается автоматически по фразам:

- «премортем», «premortem», «premortem this», «run premortem»
- «найди дыры в плане»
- «посмотри со стороны на план»
- «что может убить [план]?»
- «что я упускаю в [план]»
- «future-proof this [plan/launch]»
- «what could kill this [plan]»

Примеры запросов:

- «premortem this: запускаю $297 live workshop по Claude Cowork для
  marketing-команд»
- «stress-test найма — первый маркетолог, junior, $60k base»
- «найди дыры — выкатываем новый прайсинг через 2 недели»
